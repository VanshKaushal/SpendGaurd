03 / A SMALL LOCAL CORE

Fits into your
existing workflow.

Register Spend Guard as your agent's MCP provider. It connects to your upstream stdio or HTTP provider and forwards permitted calls.

CODING AGENT↓SPEND GUARD↓PAID MCP PROVIDER

Local policy. YAML rules and task context remain with you.

Local records. Hash-chained SQLite decisions and execution evidence.

Human approval. Use a controlling terminal or a protected local inbox in your browser.

THE CURRENT BOUNDARY

Single agent, single repository. Protection covers calls routed through the proxy. Provider prices must be configured. This core does not control model subscriptions or every cloud bill, and execution evidence does not prove code quality.

04 / RUN IT YOURSELF

Your machine.
Your spending rules.

The local core is free to download. You need Node.js 24 or later and a stdio or HTTP MCP provider. Start with the included simulated walkthrough before connecting paid tools.

Download v0.3.0 ↓

npm package archive · Local install · No account required

1

Install the downloaded archive

npm install -g ./spend-guard-0.3.0.tgz

Run from the folder containing your download. In Windows PowerShell, use npm.cmd if script execution is restricted.

2

Try the local walkthrough

spendguard demo
spendguard dashboard --ledger .spendguard/demo/ledger.db

Inspect simulated requests, duplicate blocks, and the read-only local audit dashboard before real-spend setup.

3

Connect the MCP sandbox

Initialize the local sandbox and register the generated configuration with your agent. Open the private approval inbox from proxy stderr. Sandbox responses and prices are simulated; no purchase is made. See the engineering page for the full walkthrough.

spendguard init --sandbox --config .spendguard/sandbox.yaml --repo .
spendguard mcp-config --config .spendguard/sandbox.yaml --ledger .spendguard/sandbox.db --approval browser

05 / THE PAYMENT BOUNDARY

Policy first.
Wallet authorization next.

For Solana and paid-resource workflows, the useful control point is before the purchase is authorized. Spend Guard can provide that policy decision while an external wallet or signing component handles payment.

REQUEST→POLICY→EXTERNAL SIGNER

External wallet integration contract tested locally. Live Solana settlement has not been validated.

The guard does not store private keys, take custody, or present this demo as an on-chain transaction.
