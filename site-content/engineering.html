01 / THE TRUST BOUNDARY

Before a provider runs.

CODING AGENT↓POLICY + APPROVAL↓MCP PROVIDER

Hard limits first. Budget and duplicate blocks cannot be approved away. Unknown prices and internal errors fail closed.

One-use review. The local inbox binds a decision to task, arguments fingerprint and configuration. Changes during review invalidate approval.

Conservative recovery. Interrupted authorizations keep their budget reservation. Recovery reports unresolved requests without retrying or releasing funds.

The guard covers routed tools. A local process with the same filesystem rights can bypass it or rewrite the ledger. Hash chaining detects changed records; independent checkpoints are needed for a stronger tamper boundary. Model subscriptions and unrelated cloud bills remain outside coverage.

04 / RUN AND REVIEW

Try the protocol.
Inspect the decisions.

Install the release, initialize the local sandbox, and register the generated MCP configuration with your agent. The sandbox uses real MCP transport with simulated prices and makes no purchases.

spendguard init --sandbox --config .spendguard/sandbox.yaml --repo .
spendguard doctor --config .spendguard/sandbox.yaml
spendguard mcp-config --config .spendguard/sandbox.yaml --ledger .spendguard/sandbox.db --approval browser

Open the private approval inbox URL from the proxy's stderr. Ask the agent to use search, approve once, then repeat the same query and inspect its block. Keep approval capabilities out of screenshots and shared logs.
